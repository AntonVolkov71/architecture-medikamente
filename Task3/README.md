## Оценка Data Encryption at Rest and In Transit

## Цель
- какие данные есть - почему их нужно защищать - как мы их защищаем
- защита данных в разных состояниях
- какие инструменты для этого используем

## Данные в системе
### Персональные данные (PII)
- ФИО
- дата рождения
- телефон
- email
- адрес

- Риск: утечка персональных данных, штрафы, репутационные потери.


### Медицинские данные (PHI)
- диагнозы
- назначения
- результаты анализов
- медицинская карта
- 
- Риск: самый высокий. Это медицинская тайна.

### Финансовые данные (FIN)
- суммы оплат
- чеки
- статусы платежей
- идентификаторы заказов

- Риск: мошенничество, финансовые споры.


### Согласия пациента
- согласие на обработку данных
- цель обработки
- срок
- отзыв согласия

- Риск: незаконная обработка данных без согласия.

### Логи и аудит
- кто читал данные
- кто менял данные
- когда и откуда

- Риск: удаление следов или невозможность расследования.


## Защита данных
### При хранении (at rest)
- Все PII, PHI и FIN шифруются (AES-256).
- Диски серверов шифруются (BitLocker ).
- Ключи хранятся отдельно (Vault/KMS).

### При передаче (in transit)
- Везде используется TLS 1.2+.
- С лабораторией и платёжным шлюзом - только защищённые соединения.

### При использовании (in use)
- Доступ по ролям (RBAC).
- Дополнительная проверка по атрибутам (ABAC).
- Врач видит только своих пациентов.
- Обязательно ведётся аудит доступа.
- Телефон и email - маскирование.


## Контроль и мониторинг
### IAM (Keycloak)
- вход в систему
- роли
- MFA

### Consent Management
- хранение согласий
- проверка перед обработкой данных

### Audit & Logging
- запись всех действий с PII и PHI

### DLP Engine
- проверка выгрузок в аналитику
- поиск утечек

### SIEM
- отслеживание подозрительной активности
- уведомления об инцидентах

## Аналитика
### Data Lake
- хранит выгрузки из CRM
- данные зашифрованы
- данные размечены тегами

### Analytics Platform
- строит отчёты
- работает только с разрешёнными данными
- проверяет теги перед доступом

## Результат
- Все важные данные разделены на классы (PII, PHI, FIN).
- Для каждого класса есть защита при хранении, передаче и использовании.
- Есть аудит, контроль согласий и мониторинг.
- Аналитика не получает прямой доступ к "сырым" медицинским данным.
