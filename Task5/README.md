## Разработка cutover-плана
- 

### Стратегия
- выбираем parallel Run
- обьяснение выбора
  - если сделать жесткое переключение, то в текущем это сразу все процессы перевести на новые сервисы, это приведет:
    - потеря данных, простой работы, проблемы с оплатами, не будет отката
- что получим
  - запуск новой платформы рядом со старыми процессами
  - постепенный перевод данных
  - проверка корректности данных
- смириться (минусы)
  - временное дублирование данных
  - сложность синхронизации

### Подход к стратегии
- старая система (процессы) остаются рабочими
- сначала переносим только запись к врачу (на этапе MVP), далее
  - биллинг, интеграции (ККМ, лаборатория), аналитика
  - как начнет ровно работать, отключим старые процессы и уберем Excel

### Учитывать на всех этапах критические моменты
- синхронизация данных в период миграции
- корректность ролей доступа
- согласия пациентов
- корректность биллинга
- логирование

### План отката
- Если новая система работает нестабильно:
  - временно переключить запись обратно на Excel 
  - отключить портал
  - продолжить работу в старом контуре
  - провести анализ инцидента
  - исправить и повторить тестовый запуск
- Обязательное условие:
  - ежедневные бэкапы
  - RPO = 1 день
  - RTO ≤ 4 часа


### The роли
- Архитектор - общая стратегия
- DevOps -инфраструктура и мониторинг
- Backend - CRM, IAM, интеграции
- Data-инженер - миграция данных
- Бизнес-аналитик - контроль корректности
- Руководство - принятие решения о переключении
